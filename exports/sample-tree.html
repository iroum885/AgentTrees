##结论

本仓库只有**一套 hook 机制**：MiniMax Code 的 **Plugin Hook**，定义在 `hooks/hooks.json`，由 `.minimax-plugin/plugin.json:19` 的 `"hooks": ["hooks/hooks.json"]` 注册。除此之外没有任何 git hook、npm script 之类的其他 hook（`.git/hooks/` 里只有 Git 自带的 `.sample` 模板，无启用项）。

## 11 个 hook 事件

全部指向**同一个同步命令处理器** `node "${PLUGIN_ROOT}/scripts/collect.mjs"`（Windows走 `commandWindows` 的反斜杠版本），type均为 `command`，且都**没有配置 matcher**，即监听所有工具 / 所有触发源。

| `SessionEnd` | 3s | `session_end` |
| `UserPromptSubmit` | 5s | `user_prompt` |
| `PreToolUse` | 5s | `tool_call` |

## 这一个 handler 做的事（`scripts/collect.mjs`）

1. 读 stdin 的 hook payload（JSON），取出 `hook_event_name` / `session_id` / `cwd` / `turn_id` / `transcript_path`。
2. **增量尾读 transcript**，把 assistant 的 `thinking` / `text` 块抽成 `reasoning` 事件——因为 hook payload 本身不携带思考文本。
3. 把当前 hook 事件本身追加写入 `<工作区>/.plugintree/events/<session>.jsonl`。
4. **每个事件之后都重写一次当前回合的树**，所以页面上的节点随 Agent 工作实时生长，不用等回合结束。
5. 把该工作区登记进全局 registry，供查看器的 workspace 切换器使用。
6. 用 `withLock` 文件锁串行化并发 hook 调用；**永远不写 stdout、永远 `exit 0`**，采集失败不可能阻塞 Agent 回合（fail open）。
